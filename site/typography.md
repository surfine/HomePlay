# 官網中文排版規矩

適用範圍：`site/` 產生的所有頁面（首頁、2.0 Preview、小工具往事、404），三種語言。
來源：SkyWT 的 [chinese-web-typography](https://github.com/Skywt2003/chinese-web-typography)（MIT）。
我們採用它的推理，不照抄它的數值、不引入它的字型；下方每一條都寫成這個倉庫的做法。

兩支工具（都在 `site/` 跑）：

```sh
npm run typo                  # 檢查：空距、標點、引號。npm run check 也會跑它
npm run build && npm run typo:probe -- http://127.0.0.1:4390/   # 量實際換行
```

`typo:probe` 用本機 Chrome 在 375／768／1440 三個寬度載入頁面，列出每個標題的
行組成、最後一行只剩幾個字的段落、以及被拆開的產品名。它只量測，不改東西。

---

## 一、中英與中數的邊界要有空格

- 寫在文案裡，是真正的空格：「10 款錶面」「Mac 上」「1984 年」「16°」。
- 全形標點前後不加空格：「v1.0.2，macOS 14 以上」，不是「v1.0.2 ， macOS」。
- 中文引號內外不加空格：「他說「好」」，不是「他說 「好」」。
- 只用一種策略：文案裡有真空格，所以 CSS 明確關掉瀏覽器的自動間距（`text-autospace: no-autospace`），不疊兩層。
- **不用 pangu.js**。它會把「說“好”」改成「說 “好”」，那是它的意見，不是中文慣例；本倉庫的檢查是上面這三條的最小集合。
- 例外：程式碼、URL、指令、產品識別字照原樣（`<code>` 裡的內容不檢查）。

## 二、短語意單位不要被拆行

- 產品名與數量詞在 build 時換成不斷行空格（`scripts/build.mjs` 的 `typo()`）：
  `System 6`、`Smart Stack`、`Liquid Glass`、`Apple Vision`、`HomePlay Home`、
  `CarPlay Ultra`、`Mac App Store`；以及「10 款」「12 章」「44 秒」這種數字＋量詞。
- 只保護短名。外側仍是普通空格，所以整組還是可以換到下一行；不要讓保護造成橫向捲動。
- 段尾孤字：長文靠 CSS（`line-break: strict` 讓標點不落在行首、`text-wrap: pretty`）。
  少數行銷段落（首頁 lede 這類）才手工把最後詞組包 `<span class="nb">`，例如
  `<span class="nb">喇叭出來。</span>`。**不要**對所有段落自動綁最後 N 個字——那會切斷詞，也會改變後面每一處換行。

## 三、短標題的換行要刻意

- 標題用 `text-wrap: balance`；需要指定行組成時才用 `<br>` 或行容器（`<span class="l">`），並只在對應寬度生效。
- 改一行組成後，要重新量**切換點上下的寬度**，不是只看兩張截圖。
- 左欄只有一半寬的標題（首頁「為什麼是一雙眼睛？」）收一階字級讓它一行，不要讓它折在「一雙 / 眼睛？」。

## 四、產品名要好讀

- 單字產品名（HomePlay、HomeView、ClioTalk、CarPlay）不會被瀏覽器拆開，不需要處理。
- 含空格的短名見第二條。長名要分組保護，例如 `Studio` + `Note Pro`，組與組之間要保留換行機會。

## 五、置中標題的標點要視覺置中

- 全形句號佔一格，置中後整行看起來偏左。工具是 `<span class="hang">。</span>`
  （`width: 0; overflow: visible`，句號仍是真文字），只給**置中**標題用。
- **首頁 h1 不能用**：那一行是漸層文字（`background-clip: text` + `color: transparent`），
  懸掛讓句號的框變成 0 寬，背景裁不到它，句號會整顆消失（2026-10-26 實測）。
  這種標題就讓每行各自用行容器置中，接受句號造成的偏移。
- 左對齊的標題也不要懸掛：標點會壓到前一個字。
- 不要對所有標題套同一個位移（例如 0.5em）：那取決於字形、字體與換行。

## 六、字級與字體保守處理

- 中文標題**不加英文的負字距**。漢字沒有側邊空白，`-.035em` 在 68px 是 -2.4px，字會黏在一起。
  規則寫在 `style.css`（`:lang(zh)` 給安全值 0）與各頁的 `:lang(zh)` 覆寫（首頁 h1 用 `-.008em`）。
- 簡體頁用 **PingFang SC**、繁體頁用 **PingFang TC**（`body:lang(zh-Hans)` 覆寫字體堆疊）。
  簡體落到 TC 字型會出現舊字形或 fallback 混排。
- 不用 `letter-spacing` 假裝中英間距；不壓縮全形標點；不引入 Apple 的私有字型。

---

## 新增或修改文案時

1. 中英、中數邊界留空格；全形標點與中文引號旁不留空格。
2. 跑 `npm run build && npm run typo`。
3. 跑 `npm run build && npm run typo:probe -- <本機網址>`，看三個寬度：
   - 標題有沒有折在不該斷的地方
   - 段落最後一行是否只剩 2–3 字（長文可接受，行銷段落要修）
   - 有沒有產品名被拆開
4. 修孤字時只動那一段，改完**重新量三個寬度**（換行點會連鎖改變）。
5. 手機與桌面都要看：`open http://127.0.0.1:4390/` 並拉窗寬。

## 不做的事

- 不跑整頁 DOM 改寫（`pangu.spaceNode`、`autoSpacePage`）。文案是我們自己的，在 build 時處理就好。
- 不對所有段落綁定最後 N 個字；不關閉整段換行。
- 不用 CSS 自動間距疊在真空格上。
- 不為了「寫實」而猜字型授權；只用系統字（SF + PingFang）。
